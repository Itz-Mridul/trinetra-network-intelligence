1. TOP FINDINGS THAT CHANGE YOUR PLAN

F1  YOUR IDEA IS NOT EMPTY SPACE. Three close, published systems exist.
      - Wi-Pi (IIT Hyderabad): fixed Raspberry Pi nodes measure RSSI, packet loss, RTT -> floor heat map.
        AINTEC 2014 (ACM) + IEEE SKIMA 2015 follow-up for multi-floor buildings, with open code.       [V]
      - Netrics (Univ. of Chicago): Pi at the router; joint Wi-Fi vs access-link throughput in 52 homes;
        ACM IMC 2024.                                                                                   [V]
      - SigCap (Univ. of Chicago / Notre Dame): rootless Android app logging LTE/NR cell data, Wi-Fi scans
        and GPS; crowdsourcing platform.                                                                [V]
    => Never write "first low-cost distributed Wi-Fi heat-map probes" or "first wired-vs-Wi-Fi bottleneck
       separation". Cite all three and differentiate (section 2).

F2  THE OPEN HOLE IS "WHY", NOT "WHETHER".
      - The IMC'24 authors say they can show that Wi-Fi bottlenecks exist but cannot say what causes them.   [V]
      - ML Wi-Fi troubleshooting (CCNC 2019) works from MAC-layer data exported by the Wi-Fi stack and covers
        Wi-Fi only.                                                                                     [V]
      - WiSlow (INFOCOM 2014) needs packet capture on client machines and covers Wi-Fi only.            [V]
      - ISP monitors (ISP-Checker, internet-pi, ...) have no Wi-Fi layer.                               [V]
    => PiProbe's publishable core = cross-layer ROOT-CAUSE ATTRIBUTION (ISP/WAN vs router/LAN vs Wi-Fi
       coverage vs Wi-Fi contention/interference vs probe-local vs cellular), validated with GROUND-TRUTH
       FAULT INJECTION and an open labelled dataset.

F3  CELLULAR HAT IS EXPENSIVE FOR GOOD REASON, BUT YOU DO NOT NEED IT.
      Waveshare SIM7600G-H HAT in India: Rs 6,100-7,650 (ThinkRobotics, Robu, Robocraze).                [V]
      Cheaper, global-band alternative: SIM7670G-LNGV breakout, Rs 1,575 ex-GST (about Rs 1,860 incl. GST)
      direct from Sharvi Electronics; Rs 2,574 on Amazon.in.                                           [V]
      Zero-cost alternative: spare Android phone + SigCap (4G + 5G NR + Wi-Fi scan + GPS, dual-SIM capable).

F4  BAND CHECK DECIDES WHICH MODULE YOU CAN BUY (BSNL!).
      BSNL's main 4G coverage layer is Band 28 (700 MHz); Jio's main data layer is Band 40 (2300 MHz).     [V-a]
      A7670C / A7672S cover B40 but have NO B28 -> blind to BSNL's primary layer.                          [V]
      A7670E has no TDD bands (no B40) per SIMCom's own table, although a popular Indian tutorial says
      otherwise -> do not buy A7670E for India.                                                           [V]
      Only the "G" (global) parts - SIM7670G / A7670G - list both B28 and B40/B41.                         [V]

F5  ESP32 CANNOT MEASURE FAST WI-FI. Espressif's own lab figures: about 20 Mbit/s TCP and 30 Mbit/s UDP over
    the air (ESP32, S3, C3 class). Indian FTTH plans are 100-1000 Mbps. Use ESP32 for coverage, latency,
    jitter, loss, RSSI/channel. Use Pi/laptop/phone clients for capacity.                                [V]

F6  ESP-IDF IPERF EXAMPLE SPEAKS iperf2, NOT iperf3. Your guide says "iperf3 server on Pi" - ESP32 needs an
    iperf (v2) server. Run both.                                                                         [V]

F7  OPERATOR COVERAGE MAPS ARE OUTDOOR PREDICTIONS. Jio and Airtel state coverage = predicted RSRP >= -110 dBm
    at outdoor cell edge, and say indoor availability differs. Indoor validation = open, India-relevant gap. [V]

F8  CLASSIC ESP32 IS 2.4 GHz ONLY. ESP32-C5 (dual-band 2.4/5 GHz Wi-Fi 6) is in mass production since Apr 2025;
    dev kits US$9-15 (Waveshare C5-Pico US$8.99).                                                       [V]

F9  REGULATORY HOOK. TRAI Standards of QoS Regulations 2024 (effective 1 Oct 2024): latency benchmark below
    50 ms wireline / below 75 ms wireless (tightening to 50 ms), new jitter and packet-drop parameters,
    mandatory operator coverage maps. Use as reference lines and "indicative compliance" mapping (these are

F10 PRIVACY LAW. DPDP Rules 2025 notified 13/14 Nov 2025 with 18-month phased compliance (core duties about

Format: CITE / LINK / WHAT THEY DID / WHAT THEY DID NOT DO (per abstract) / HOW PiProbe DIFFERS

2.1  Wi-Pi  [V]
  CITE : D. Bhardwaj, K. Kataoka, V. Kumar, "Wi-Pi: Distributed Wi-Fi Performance Assessment using Raspberry
         Pi," Proc. 10th Asian Internet Engineering Conf. (AINTEC), pp. 31-36, 2014. DOI 10.1145/2684793.2684798
  ALSO : D. Bhardwaj, K. Kataoka, V. Vikram, V. Hirani, "Hybrid approach to distributed Wi-Fi performance
         assessment for multi-floor structures," IEEE SKIMA 2015. DOI 10.1109/SKIMA.2015.7400037 (IEEE Xplore 7400037)
  CODE : https://github.com/imvikash00/Network_management_using_raspberryPi
  DID  : Stationary Raspberry Pis across an IIT Hyderabad campus network measured RSSI, packet loss and RTT to a
         server and drew geographic heat maps; 2015 follow-up mixed Pis with smartphones in multi-floor buildings.
  NOT  : (per abstracts) no separation of ISP/WAN from Wi-Fi faults, no fault classification, no cellular layer,
         no ground-truth fault injection, 2014-era Wi-Fi, Pi-class nodes.
  DIFF : ESP32-class nodes (cost/power), wired baseline + WAN tests, cause attribution with injected faults,
         cellular overlay, dual-band, open labelled dataset, calibration study.

2.2  Netrics / WiFi-bottleneck study  [V]
  CITE : R. Sharma, M. Richardson, G. Martins, N. Feamster, "A Longitudinal Study of the Prevalence of WiFi
         Bottlenecks in Home Access Networks," ACM IMC 2024 (Madrid). DOI 10.1145/3646547.3689007
         (preprint: arXiv:2311.05499, "Measuring the Prevalence of WiFi Bottlenecks in Home Access Networks").
         Author list above is from the arXiv version - confirm on ACM DL.
  CODE : https://github.com/internet-innovation/netrics  (data: https://github.com/internet-innovation/netrics-data)
  DID  : Pi at the router ran NDT7/Ookla/iperf3 for access throughput; a browser plug-in measured Wi-Fi throughput
         to a speed-test server on the Pi. 52 households (65 vantage points), Sep 2021 - Jun 2023, 13,581 joint
         samples. Wi-Fi was the bottleneck every time for access tiers above 800 Mbps.
  NOT  : authors state they cannot attribute the cause of the bottleneck; Wi-Fi samples exist only when a user
         device is active; throughput focus (latency/loss not analysed in that paper); Chicago only.
  DIFF : always-on fixed probes (user-independent), per-room spatial resolution, RSSI/channel/neighbour APs,
         latency/jitter/loss, cause attribution, cellular, India.

2.3  Wi-Fi pathology diagnosis with ML  [V]
  CITE : I. Syrigos, N. Sakellariou, S. Keranidis, T. Korakis, "On the Employment of Machine Learning Techniques
         for Troubleshooting WiFi Networks," IEEE CCNC 2019, pp. 1-6. DOI 10.1109/CCNC.2019.8651823
  DID  : MAC-layer exported data -> four tuned classifiers -> diagnose five common Wi-Fi pathologies
         (contention, low SNR, non-802.11 interference, ...).
  NOT  : Wi-Fi only (no ISP/WAN/LAN split); needs MAC-layer statistics from the Wi-Fi stack.
  DIFF : black-box, end-to-end features from commodity probes; multi-domain taxonomy; wired baseline.

2.4  WiSlow  [V]
  CITE : K.-H. Kim, H. Nam, H. Schulzrinne, "WiSlow: A Wi-Fi network performance troubleshooting tool for end
         users," IEEE INFOCOM 2014. DOI 10.1109/INFOCOM.2014.6848014 (IEEE Xplore 6848014)
  DID  : user-level probes + packet-loss analysis + 802.11 ACK-pattern analysis to tell channel contention from
         non-Wi-Fi interference; peers collaborate to locate the source.
  NOT  : needs capture on client machines; Wi-Fi only; no WAN layer; not a fixed building deployment.
  DIFF : fixed probes, WAN/LAN baseline, no promiscuous capture of other people's frames required.

2.5  SigCap (cellular + Wi-Fi mapping from phones)  [V]
  LINK : https://people.cs.uchicago.edu/~muhiqbalcr/sigcap/   (data platform: https://sigcap.crc.nd.edu [V-a])
  CITE : M. I. Rochman et al., "A comprehensive analysis of the coverage and performance of 4G and 5G deployments,"
         Computer Networks, vol. 237, 2023, art. 110060 [V-a]. Also V. Sathya, M. I. Rochman, M. Ghosh,
         "Measurement-based coexistence studies of LAA & Wi-Fi deployments in Chicago" [V-a; venue: check].
  DID  : Android API logging of LTE (PCI, EARFCN, RSRP, RSRQ), NR (SS-RSRP/RSRQ) and Wi-Fi (BSSID, channel,
         RSSI) with GPS, no root. 2026 preprint arXiv:2607.16008 uses SigCap Wi-Fi beacon logging in a stadium.
  NOT  : mobile/passive survey; no wired baseline; no continuous fixed probes; no fault attribution; US sites.
  DIFF : fixed continuous probes + active tests + wired baseline + India operators; SigCap is the right
         reference instrument for your cellular cross-check.

2.6  CheesePi  [V]
  CITE : L. McNamara, I. Marsh, "CheesePi: A Raspberry Pi based measurement platform," IRTF/ISOC RAIM workshop 2015;
         and "CheesePi: Research, Results, and the Regulator," ACM ANRW 2017, DOI 10.1145/3106328.3106337
  CODE : https://github.com/liamjjmcnamara/cheesepi
  DID  : always-on Pi agents measure home Internet quality; worked with the Swedish regulator.
  NOT  : no Wi-Fi diagnosis layer, no ESP32 sensors, no floor-plan mapping.

2.7  BISmark (gateway-based broadband measurement)  [V]
  CITE : S. Sundaresan, W. de Donato, N. Feamster, R. Teixeira, S. Crawford, A. Pescape, "Broadband Internet
         Performance: A View From the Gateway," ACM SIGCOMM 2011, pp. 134-145. DOI 10.1145/2018436.2018452
  NOTE : classic reference for measuring from the gateway; speed-test design later fed national programmes.

2.8  Home network vs access link (passive inference)  [V]
  CITE : S. Sundaresan, N. Feamster, R. Teixeira, "Home Network or Access Link? Locating Last-Mile Downstream
         Throughput Bottlenecks," PAM 2016, LNCS 9631, pp. 111-123. DOI 10.1007/978-3-319-30505-9_9
  NOTE : found wireless bottlenecks more common than access-link bottlenecks for faster plans; indirect inference.

2.9  MONROE  [V]
  CITE : Ö. Alay et al., "Experience: An Open Platform for Experimentation with Commercial Mobile Broadband
         Networks," ACM MobiCom 2017, pp. 70-78. DOI 10.1145/3117811.3117812
  NOTE : multi-operator mobile-broadband nodes (homes, trains, buses) + open datasets; Europe; heavy hardware.
         Use as the methodological reference for multi-operator comparison design.

2.10 ESP32 + Pi decoupled monitoring (security focus)  [V-a]
  CITE : "Monitoring Wireless Networks Using a Low-Cost, Decoupled ESP32-Based Architecture," IEEE Xplore document
         11208386 (about 2025; confirm venue/authors on the page).
  DID  : ESP32 as 802.11 packet listener, relays frames to a Pi over SPI, Suricata IDS on the Pi.
  NOT  : security use-case, not QoS / fault attribution. Cite as ESP32+Pi architecture precedent.

2.11 Probe-selection from shared latency anomalies (Netrics group)  [V-a]
  CITE : "Less is More: Optimizing Probe Selection Using Shared Latency Anomalies," arXiv:2602.03965 (2026).
  NOTE : inter-home probes on Pi 4B at routers (99 devices, Apr-Jul 2022). Relevant to your multi-probe
